# Knowledge acceptance

Accept a knowledge item only when evidence and executable checks support the stated claim. Record assumptions, scope, uncertainty, counterexamples, code paths, and source revisions. Link null and contradictory results as well as supporting ones.

Keep statistical and causal claims separate. Software tests can establish contract behaviour; they cannot establish a segmentation claim from synthetic fixtures alone.

For a new claim, keep the initial text as proposed. Record acceptance and evidence versions separately. When later evidence changes support or scope, version the claim and mark the previous version superseded or suspended.
